# Бриф для разработки врагов этажа 3

## Короткий ответ

Для начала разработки механик и кода 3D-модели не обязательны: в приложенном
`FLOOR3_ENEMY_AGENT_SOURCES.txt` есть текущие конфиги, точки, логика этажа и
примеры работающих врагов этажей 2, 4 и 5. По ним можно подготовить новые типы
врагов и интеграцию.

Модели/риги понадобятся для точной подгонки силуэтов, размеров частей, оружия,
анимационных точек и визуальных эффектов. Карта или её превью понадобятся для
визуальной проверки врагов в окружении. Для первой кодовой итерации достаточно
текущих исходников, координат и согласованного описания мобов.

## Что уже есть в проекте

- Этаж 3 зарегистрирован в `FloorService` как `Floor3` + `Floor3World`.
- `Config/Floor3.lua` содержит конфигурацию зон, волн, ловушек и точки размещения.
- В текущих волнах используются временные типы с этажей 1–2: `shade`, `guard`,
  `guard_elite`, `archer`, `knight`, `knight_elite`, `martyr`, `ranger`, `bee`,
  `drowned`, `gardener`, `treant`.
- `Floor3World.lua` уже реализует механику мира: грязь/дёготь, капканы, растяжки,
  стены-секреты, клетки, мост, телегу, люстры, трофеи, жаровни и насесты ловчего.
  Не заменять и не удалять эти системы при добавлении врагов.
- Общие боевые правила и расчёт характеристик находятся в `EnemyService.lua` и
  `Config/Enemies.lua`. Визуальный контроллер читает `EnemyVisuals` и префабы
  `ReplicatedStorage.EnemyPrefabs.<typeId>`.
- Примеры новых типов и стиля интеграции — этаж 2 (`Floor2Service`, `Treant`,
  `Bee`) и этажи 4–5 (`Enemies45`, `EnemyVisuals45`, `Floor45Service`).
- Общий `EnemyFx` вызывается через `EnemyVisualController`; `EnemyAura` —
  необязательный дополнительный модуль для постоянных частиц/света/вращения.

## Правила интеграции

1. Сначала согласовать список мобов: `typeId`, имя, роль, зоны/волны, поведение,
   основные атаки и телеграфы. Не менять баланс, награды и состав волн без
   отдельного согласования.
2. Использовать новые уникальные `typeId`; не переопределять имена этажей 1–2.
   В `Floor3.lua` заменить только те временные идентификаторы, которые владелец
   решит заменить. Сохранить координаты, триггеры и порядок волн, если изменение
   планировки отдельно не запрошено.
3. Новые характеристики хранить в отдельном `Config/Enemies3.lua` либо в
   существующем `Config/Enemies.lua` — выбрать один способ и согласовать его.
   При отдельном модуле добавить его в таблицу `Enemies.Types` по образцу
   объединения `Enemies45.Types`; не затирать базовые типы.
4. Визуальные наборы хранить отдельно (`EnemyVisuals3.lua`) либо добавить в
   существующий `EnemyVisuals.Types` по тому же принципу, что `EnemyVisuals45`.
   Для типа указать уникальный набор анимаций, роль, масштаб, атаки и звуки.
5. Для атаки, которая помещается в стандартную схему `EnemyService`, сначала
   использовать поля `attacks` из `Enemies.lua`. Особую механику реализовывать
   отдельным сервисом/attacher по примеру `Floor2Service` или `Floor45Service`,
   подключать из Bootstrap и регистрировать через `EnemyService.spawnHooks`.
   Хук должен фильтровать только собственные `typeId`; spawn hooks глобальны.
6. Не встраивать мобов в геометрию карты, если для них предполагаются отдельные
   префабы/риг. Меши, риги и код сборщика поставлять отдельно. Текущий сборщик
   этажей 4–5 (`tools/studio/AssembleEnemies45.lua`) и `EnemyRig4/5.lua` — примеры
   формата, не готовый сборщик этажа 3.
7. Интеграционные общие файлы (`Enemies.lua`, `EnemyVisuals.lua`, `Bootstrap`,
   `FloorService`, `EnemyFx`, `Resolve`) править точечно: сохранить текущую
   функциональность этажей 1–5, особенно Floor3World и поддержку этажей 4–5.
8. Если готовые модели ещё не предоставлены, сначала завершить кодовую схему и
   временные визуалы. Не придумывать геометрию модели или расположение деталей
   по одному текстовому описанию.

## Нужные данные от автора мобов

- Для каждого моба: `typeId`, имя, роль, рост/радиус, здоровье, броня, скорость,
  атаки и награды (если их разрешено менять).
- Для особых действий: момент телеграфа/удара, зоны поражения, длительность,
  состояние после атаки, ограничения/контр-игра игрока и нужные события FX.
- Для визуальной сборки: GLB без Merge, имена мешей с согласованным префиксом,
  риг с центрами частей/суставами, точки FX и список анимаций.
- Для финальной проверки: карта Floor3 или её превью и точки, где надо проверить
  масштаб/коллизии/видимость.

## Проверки перед передачей

- Все новые `typeId` разрешаются через `Enemies.stats` и имеют визуальную запись.
- Все анимационные наборы перечислены в `Shared/Anim/Resolve.lua`; их модули
  загружаются без ошибок и используют имеющийся формат позы.
- Каждый импортированный тип собирается в `EnemyPrefabs` с `PrimaryPart`,
  `AnimationController`, частями, суставами и FX-точками, если они заявлены.
- Сохранены существующие секреты, ловушки, боссы, Floor3World и старые этажи.
- Проверены обычное появление, бой, смерть/удаление, телеграфы, ресет комнаты и
  запуск в Studio; сообщить явно, что осталось непроверенным.

Полные исходники для чтения приложены в `agent-packs\floor3-enemies-sources.txt`.
